# Как сделать тему колеса

Актуально на 2026-09-16. Это и инструкция для людей, и бриф для агентов, которые пишут темы.

## Что такое тема

Тема — папка `src/domains/theme/themes/<id>/` с единственной точкой входа `theme.ts`, которая экспортирует
`ThemeDefinition` (тип в `src/domains/theme/model/types.ts`):

```ts
const theme: ThemeDefinition = {
  id: 'casino',
  parts: { spinningWheel, pointer, effects, coreImage? },   // что рисуется на самом колесе
  background: CasinoBackground,                             // фон всей страницы
  ui: { ...DEFAULT_UI_TOKENS, accent, headingFont, ... },   // кнопки, панели, шрифты
  select: { background, color, borderColor?, fontFamily?, icon? }, // как тема выглядит в селекте
};
```

Все `<id>` уже перечислены в `WheelStyle` (`src/models/wheel.model.ts`) и подключены в реестре
`src/domains/theme/config/themes.ts`. Подписи в селекте берутся из `wheel.style.<id>` в локалях. Ничего из
этого при написании темы трогать не нужно: правится только содержимое папки темы.

Эталон для копирования: `src/domains/theme/themes/matrix/` (четыре компонента и `theme.ts`).

## Части колеса (`parts`)

Колесо рисуется на canvas компонентом `CanvasSpinningWheel` (`src/domains/wheel/BaseWheel/parts/spinning-wheel/`).
Тема даёт ему объект `renderer` с тремя функциями. Все они получают `helpers`: `layout` и `scale`.

- `layout` (`WheelPartLayout`, `src/domains/wheel/BaseWheel/parts/types.ts`): `canvasSize` (холст больше колеса
  на 30 %), `center` (центр холста), `wheelRadius`, `targetWheelSize`, `scale` (= размер колеса / 800),
  `overflowPadding` (поле вокруг колеса на холсте).
- `scale(px)` — умножить на масштаб. Все размеры, толщины линий, шрифты и тени задаются как `scale(N)`,
  где N подобрано для колеса 800 px. Без `scale` тема ломается на других размерах экрана.

Функции рендерера:

1. `drawSlice(ctx, item, getColor, helpers)` — заливка одного сектора от `item.startAngle` до `item.endAngle`
   (радианы, 0 = «3 часа», по часовой). Цвет участника — `getColor(item)`; при подсветке другие секторы приходят
   серыми, это надо сохранять (не игнорировать `getColor`). Тема вправе перекрасить цвет в свою палитру
   (см. `toMatrixColor`), но соседние секторы должны различаться.
2. `drawText(ctx, item, helpers)` — подпись сектора. Геометрия одна для всех тем: выставьте `ctx.font`, затем
   `const { startRadius } = fitSectorText(ctx, text, layout, { outerRatio })` из
   `@domains/wheel/BaseWheel/parts/sectorText` — помощник прижимает подпись к внешней границе `outerRatio × R`
   (0.84–0.92 в зависимости от толщины обода) и уменьшает размер шрифта, если имя не помещается между
   ступицей и ободом. Дальше `translate(startRadius·cos, startRadius·sin)`, `rotate(centerAngle)`,
   `textAlign = 'left'`, `textBaseline = 'middle'`, `fillText(text, 0, 0)` (см. `MatrixWheel`). Меняйте шрифт,
   цвет, обводку и свечение. Обрезайте текст `fitText(name, 21)`. Не рисуйте, если сектор уже 1,6 % круга.
3. `afterDraw(ctx, items, helpers)` — обод, деления, виньетка, текстуры поверх секторов. Клипуйте по кругу,
   если рисуете на весь холст.

Ограничения холста колеса: он кешируется и перерисовывается только при смене участников или подсветки,
поэтому анимация в `drawSlice/drawText/afterDraw` не работает. Анимация живёт в `effects`.

Сколько можно рисовать за ободом. Страница подбирает размер колеса под высоту окна и оставляет под ним
фиксированные 16 px, поэтому на самом большом колесе (scale ≈ 1.11) наружу помещается всего ~14 единиц
макета — всё, что дальше, срезает нижний край окна. Холст колеса на 30 % больше самого колеса, и это
сбивает с толку: на холсте место есть, на экране его нет. «Пивная вечеринка» на этом и погорела — шапка
пены уходила наружу на 56 единиц (30 + 6 шума + язык подтёка 20), и низ колеса был видимо срезан. Держите
суммарный наружный вылет в пределах ~12 единиц (`MAX_OVERHANG` в `beerPartyTokens.ts`), а толщину обода
набирайте внутрь. Проверять надо не арифметикой, а сканом: найдите на холстах самый нижний непрозрачный
пиксель и сравните его экранную координату с `window.innerHeight`. Если тема кладёт что-то постоянное вдоль нижнего края,
сравнивайте с верхом этого элемента, а место под него резервируйте CSS-ом темы, укорачивая `.wheelArea`
(`html[data-wheel-style='<id>'] [class*='wheelArea_']`): размер колеса считается от высоты этой области.

`pointer` — компонент `({ layout }) => JSX`. Он может торчать над ободом не больше чем на ~0.08 размера колеса
(столько зарезервировано под него зазором `WHEEL_TITLE_GAP` = 72 px между именем победителя и ободом). Если стрелка
темы ниже, тема может уменьшить этот зазор полем `parts.titleGap` (px): колесо станет крупнее и поднимется выше
(у «Тайваня» 30 px при лапе, выступающей на 26 px). Зазор учитывают и `BaseWheel`, и `FlexboxAutosizer`. Три способа: `<img>` со сгенерированной картинкой
(см. `BeerPartyPointer`: проба загрузки и рисованный запасной вариант), SVG с классом `classes.wheelPointer` из
`BaseWheel.module.css` и `transform: translate(-50%, -36%)` (см. `MatrixPointer`), или canvas на весь холст
(см. `GenshinPointer` в `src/domains/wheel/BaseWheel/parts/pointer/`). Стрелка указывает вниз на верх колеса.

`effects` — компонент `({ layout, isSpinning }) => JSX` с собственным canvas поверх колеса (`zIndex: 2`,
смещённым на `-overflowPadding`), `requestAnimationFrame`, частота 12–30 кадров, `null` если эффектов нет.
При `isSpinning` эффект должен заметно усиливаться. Обязательно `cancelAnimationFrame` в cleanup.

`coreImage` — путь к картинке в центре по умолчанию (`/themes/<id>/core.png` в `public/`). Необязательно (у
«Солнечной системы» её нет намеренно), но у большинства тем она есть: квадратная эмблема 512 px, генерируется в Higgsfield (`gpt_image_2_5`, 1:1,
промпт «circular emblem for the hub of a fortune wheel, <стиль темы>, centered, no text») и уменьшается PowerShell-ом
(`System.Drawing`). Когда генератор картинок недоступен, эмблему можно нарисовать процедурно на canvas и
сохранить как PNG — см. `tools/matrix-core/README.md` (так сделана эмблема «Матрицы»). Фон тоже может быть картинкой из `public/themes/<id>/` (см. `highSociety`, `beerParty`): 16:9,
JPEG, персонажи справа, левая половина тёмная, поверх — градиент и лёгкий canvas-слой.
Если в сцене важен персонаж, фон рисуйте на canvas и позиционируйте картинку по его реальной доле ширины
(`MAN_ANCHOR` в `BeerPartyBackground`), чтобы он попадал в просвет справа от колеса, а не за него.

Картинка, которой ещё нет (например, фото стрелки или пены, заказанное в Higgsfield), подключается через пробу:
компонент пытается загрузить `/themes/<id>/<file>.png`, а до успеха или при 404 показывает рисованный
вариант (`BeerPartyPointer` → `BeerPartyPointerDrawn`, `foamTexture.get()` в эффектах). Так файл можно положить в
`public/` позже без правок кода. Общий загрузчик для таких файлов — `createImageAsset(src)` и хук
`useImageAsset(asset)` (`beerParty/imageAsset.ts`): и то и другое отдаёт `null`, пока картинки нет, а хук
перерендеривает компонент, когда она приедет (кеш колеса иначе так и остался бы без фото).

Фотофактура поверх секторов. Чтобы секторы были не заливкой, а настоящим напитком, положите фото сверху
**только его яркостью**: цветное фото перекрасило бы и те секторы, которые базовое колесо увело в серый на
время подсветки. `beerTexture.ts` делает из снимка пива серую копию (`globalCompositeOperation = 'saturation'`
с заливкой `hsl(0, 0%, 50%)`), приглушает контраст и **сдвигает среднюю яркость к 0.5** — без этого шага
`overlay` не «добавляет фактуру», а осветляет всё колесо, и оно выцветает. Дальше в `drawSlice` фото рисуется
через `overlay` поверх градиента, один раз на сектор, с клипом по его клину; кеш серой копии живёт на уровне
модуля, иначе она пересобиралась бы для каждого сектора.

## Фон (`background`)

Компонент без пропсов, рендерится один раз на весь экран под интерфейсом: корневой `div` с классами
`absolute inset-0 z-0 h-full w-full overflow-hidden` и своим фоновым цветом. Внутри — canvas-анимация
(эталон `MatrixRainBackground`, `GeometryBackground`), CSS-градиенты, SVG. Правила:

- частота кадров не выше 30, `cancelAnimationFrame` в cleanup, пересчёт размеров на `resize`;
- фон не должен спорить с колесом: тёмная виньетка к центру-слева (там колесо) или общая приглушённость,
  как `opacity: 0.55` у дождя в «Матрице»;
- никаких внешних картинок и шрифтов из сети; всё рисуется кодом или лежит в `public/themes/<id>/`
  (локальные веб-шрифты — в `public/fonts/<name>/`, см. «Веб-шрифты»).

## Общие ассеты

Картинки, нужные нескольким темам, лежат в `public/themes/shared/` (Vite отдаёт их как `/themes/shared/<file>`).
Сейчас там два файла, оба используют «Солнечная система» (`solarSystem/SolarSystemBackground.tsx`) и
«Далекий космос» (папка темы `genshinImpact/`, компонент `DeepSpaceBackdrop`):

- `deep-space.jpg` (2560×1448, сгенерирован в Higgsfield) — фотореалистичный глубокий космос: левая половина
  почти пустая, справа сверху крупная галактика Андромеды, справа снизу Столпы Творения.
- `team-astrophoto.jpg` (960×1101) — два настоящих снимка сотрудника команды (август 2026): Плеяды сверху,
  туманности Лагуна и Трёхраздельная снизу, склеены по вертикали с плавным перекрытием ~260 px
  (`tools`-скрипт не нужен: PowerShell + System.Drawing, полосами с нарастающей альфой). Показывается в полосе
  слева от колеса: ширина полосы = левый край колеса − 24 px (по `[class*="wheelContent"]`), уже 140 px — не
  рисуется; снимок подгоняется по ширине полосы, но не ниже ~78 % высоты (тогда режется по бокам), и все
  четыре края растушёваны, чтобы он лежал слоем поверх космоса, а не заканчивался кромкой.

Правила те же, что для картинок темы: грузить через `new Image()`, до загрузки и при ошибке показывать
процедурный вариант, пустого экрана не бывает.

### Ассеты «Солнечной системы» (`public/themes/solarSystem/`)

- `sun.jpg` 1200×1200 — фото диска Солнца (гранулы, пятна, потемнение к лимбу), вне диска чёрное. Диск
  **не по центру**: центр (588, 583), радиус 548 px; `SolarSystemWheel` растягивает именно эту окружность на
  колесо (`sunImage.ts`, `SUN_DISC`). Колесо изображает **затмение**: поверх фото лежит почти чёрный диск Луны
  (фото проступает призраком), секторы — слабые тёплые подсветки (`source-over`, альфа 0.09), на краю тонкое
  яркое кольцо хромосферы и свет короны, затекающий на лимб. Ступица — тёмный SVG data URL (`HUB_ECLIPSE` в
  `theme.ts`); её белая рамка приглушена в `solarSystem.css` через
  `html[data-wheel-style='solarSystem'] [class*='wheelCore_']`.
- `corona.jpg` 1200×1200 — корона затмения на чистом чёрном. Чёрный диск стоит **не точно по центру кадра**:
  центр (0.4975, 0.485) стороны, радиус 0.1938, стримеры до ~0.36 от него — иначе корона съезжает относительно
  колеса. Фон один раз вырезает квадрат вокруг измеренного центра (полусторона 0.47 стороны фото — шире видимых
  стримеров), уменьшает его (не больше 1100 px), переводит чёрный в прозрачность и радиально гасит края выреза до
  нуля (иначе при вращении виден диагональный край квадрата),  (альфа = яркость, цвет делится на альфу — эквивалент `screen`), а в кадре остаётся один
  обычный `drawImage` с поворотом: один оборот за 6 минут, дыхание альфы 0.7–1. Битмап собирается под измеренный
  радиус колеса, а не под сглаженный, чтобы не пересобираться каждый кадр во время анимации размера.
- `planets/<name>.png` 256 px (`saturn` 256×172 с кольцами) — фотоспрайты восьми планет, **все освещены
  слева**, правая треть в тени. Разворот на угол орбиты (направление от Солнца к планете) поворачивает
  освещённую сторону к Солнцу. Доля шара в ширине спрайта: 0.92, у Сатурна 0.42, у Урана 0.7
  (`PLANET_BODY_RATIO`). До загрузки спрайта планета рисуется процедурно.
- `pointer.png` — стрелка: фотоспрайт остриём вниз (сейчас советский космонавт в оранжевом СК-1; кандидаты — метеор, комета, ракета, астронавт, космонавт в «Орлане»,
  телескоп «Джеймс Уэбб» — лежали на выбор). `SolarSystemPointer` пробует загрузить файл и показывает его высотой
  «выступ над ободом (≤ 64 px) + 40·scale вглубь колеса», иначе рисует SVG-комету (`SolarSystemPointerDrawn`).
- `flyers/blackhole.png` 640×314 — чёрная дыра в духе «Интерстеллара». Небольшая, медленно проходит по верхней
  полосе экрана (над колесом), уходит за край, отдыхает 30–80 с и возвращается с другой стороны. Под ней фон
  **линзируется**: пять колец от радиуса спрайта до 1.9 радиуса перерисовывают уже нарисованный фон с увеличением
  от 1.42 у горизонта до 1.04 снаружи (источник — сам холст, поэтому рисуется сразу после фона, до планет).
- `flyers/{comet,asteroid,iss,probe}.png` 384 px — гости, пролетающие через кадр (`spaceFlyers.ts`): у кометы
  ядро справа, поэтому поворот на курс (`atan2(vy, vx)`) ведёт её ядром вперёд; станция и зонд летят по курсу с
  лёгким покачиванием, астероид вращается. Спрайты уменьшаются под экранный размер один раз (`scaleSprite`,
  ступенчато не больше чем вдвое за шаг), в кадре остаётся `drawImage`. Все картинки грузит `spriteImages.ts`.

Как фото ложится на экран в «Солнечной системе» (`fitBackdrop`): масштаб = `max(высота окна / высота фото,
ширина контентной области / ширина фото)` — «cover» по высоте окна и по ширине области колеса, — а затем
правый край фото совмещается с правым краем контентной области. Контентная область тянется от левого края окна
до левого края панели (`div[class*="sidebar"]`, `getBoundingClientRect().left`, замер раз в секунду тем же
таймером, что следит за колесом), а без панели (режим презентации) — до правого края окна. Зачем так: всё
интересное на фото справа, и при таком выравнивании Андромеда и Столпы попадают в просвет между колесом и
панелью, а обрезается пустой левый край, где терять нечего. Всё правее контентной области (полосу под панелью,
а в режиме презентации — только запас под дрейф) заполняет зеркальная затемнённая копия фото, чтобы на стыке не
было шва. Слой кешируется и перерисовывается только когда меняется измеренная рамка: размер окна (с задержкой
~150 мс после `resize`), положение панели или левый край колеса. Положение колеса фон меряет каждый кадр:
сдвиг больше 40 px (панель показали или скрыли) повторяется мгновенно, сглаживается только мелкое дрожание.

### Ассеты «Тайваня» (`public/themes/taiwan/`)

Всё сгенерировано в Higgsfield (варианты собирались на листы и утверждались командой) и ужато Pillow.

- `bg-a.jpg`, `bg-b.jpg`, `bg-d.jpg` 1920×1086 — ночной Тайбэй с Тайбэй 101, «две системы» через пролив (слева
  красное небо и корабли, справа Тайбэй 101 и завод чипов), ночной рынок с вывесками. Не один фон, а **ротация**
  (`TaiwanSlideshow`, список `SLIDES` в `taiwanTokens.ts`): каждые 20 с следующее фото проявляется поверх текущего
  за 2,5 с, пока фото на экране, оно наезжает до 1.05 (CSS в `taiwan.css`). Фото рисуется в 1.12 раза больше
  «cover», чтобы его `anchorX` (доля ширины, где главное на снимке) можно было сдвинуть в просвет справа от
  колеса. Левый край не открывается никогда; правый может, но только до левого края панели, а остаток (строка
  шапки над панелью) закрывает зеркальная копия с нахлёстом 1 px — без нахлёста виден шов. Следующее фото
  переключается, только когда декодировано, а уходящее остаётся первым потомком со своим `key`, чтобы React не
  переставлял его узел: перестановка перезапустила бы его наезд.
- Обода с котиками нет. Колесо — лаковые секторы почти до края (до 0.955 R, `RIM_INNER`) под тонким золотым
  ободом с лаковой канавкой и 36 заклёпками (`rim.ts`, рисуется последним шагом `afterDraw` в кеш колеса, крутится
  с ним). Имена тянутся до 0.915 R (`LABEL_OUTER`), под ободом тонкая полоска в цвете участника. Котики на ободе
  прошли три итерации (кольцо из концепта, тонкий концепт, кольцо, собранное из 54 отдельных котят) и были убраны
  по решению команды: кольцо съедало место под имена, а в жёлобе между бортиками котики выглядели «в клетке».
  Приём общий для концептов колеса из генератора: из картинки берётся только идея, секторы рисует код (иначе
  колесо не работает с любым числом участников и ломается серый режим подсветки).
- `core.png` 512 px — кот в круглом окне, кадр обрезан по кругу окна. `pointer.png` 169×360 — рыжая лапа
  подушечками вниз, верхние 32 % растворяются в прозрачность, чтобы лапа «появлялась» над ободом. Над ободом ей
  можно выступать только на 26 px (зазор под именем — 30 px), поэтому длину она набирает вглубь колеса: `DIP` = 120
  единиц макета, на 1920×945 лапа 150 px и заходит на 125 px ниже обода, на внешний край верхнего сектора (имя
  этого сектора и так написано над колесом).
- `pelosi.webp` 1022×1400 (отражена, смотрит на колесо), `buffett.webp` 712×900 (смотрит вверх-влево),
  `plane.webp` 1000×406 (правительственный C-40C в три четверти) — Seedream 5.0 Pro, фон вырезан самим генератором
  (`--remove_bg true`) или `image_background_remover`. Крупные фото с прозрачностью — WebP: PNG того же размера
  весил бы 1–2 МБ. `cat-left.webp` (рыжий котёнок в прыжке) и `cat-right.webp` (табби выглядывает из-за края,
  отражён) — тоже Seedream, из шести кандидатов. Всех ставит измеренная рамка `useWheelFrame` (квадрат колеса и
  левый край панели, пять раз в секунду): Пелоси — у левого края на всю высоту окна, лицом в середине левого
  просвета; Баффет — маленький, вплотную к правому краю области колеса (левому краю панели или краю окна); котики —
  на всю высоту, котёнок слева, табби у правого края. Котёнок широкий и заходит под колесо, поэтому он, как и
  бегущая строка, рендерится порталом в `<body>` поверх колеса (z-index 140, строка 150): иначе его мордочку закрывало
  колесо. Табби остаётся в фоне — его мордочка и так правее колеса.
- **Программа прокрута.** Персонажи не стоят всё время, а разыгрываются по секундам от начала прокрута
  (`SPIN_PROGRAM` в `taiwanTokens.ts`), и так на каждом прокруте:

  | номер | с | до |
  | --- | --- | --- |
  | самолёт Пелоси | 9 | пролёт 9 с |
  | Airbus | 20 (через 2 с после её самолёта) | пролёт 9 с |
  | котёнок слева, быстро выпрыгивает | 35 | 42 |
  | табби справа, медленнее | 39 | 42 |
  | Пелоси слева | 42 | 54 |
  | Баффет справа | 48 | 54 |
  | бегущая строка снизу | 52 | 54 |

  Время прокрута фон узнаёт из `spinTimelineStore` (`domains/wheel/lib`): `WheelBoard` пишет туда старт с
  длительностью и остановку. `useSpinMoment` вызывает пролёт в свою секунду, `useSpinWindow` держит номер на сцене
  от `from` до `to` (`useSpinCue.ts`). Номер начинается, только если колесо ещё крутится на `from`, но раз начавшись,
  доигрывает до `to`, даже если колесо уже остановилось; прокрут короче `from` его пропускает. Выезд и уход — CSS-переход
  `transform` (класс `.taiwan-enter`, `data-shown`): Пелоси и котёнок уезжают за левый край, Баффет, табби и строка — за
  правый и нижний; котёнок выпрыгивает за 320 мс с перелётом, остальные — за 900 мс.
- Самолёты с круглыми портретами над фюзеляжем: у правительственного — Пелоси (`pelosi-badge.webp` 256 px, вырезан
  из исходного фото с тёмным фоном, а не из вырезки), у белого Airbus — пассажир (`passenger.webp` 256 px, аватарка
  члена команды). `airbus.webp` 1000×405 сгенерирован Seedream с референсом-изображением правительственного
  самолёта, поэтому ракурс и кадр совпадают. Оба идут одним путём сверху справа за колесо (Web Animations API), в
  середине пути под каждым на ~3 с проявляется своя дата: «2 августа 2022» и «27 сентября 2026». Самолёт с
  подписью — `FlightSprite`, запуск по программе — `PlaneFlyover`.
- Бегущая строка «Пелоси ▲ · Баффет ▲»: обе стрелки зелёные, у неё огромная, у него крошечная. Строка 30 px
  (`TW_TICKER_HEIGHT`) выезжает целиком снизу **поверх** колеса: она рендерится порталом в `<body>` с `position: fixed`
  (фон лежит под приложением, поверх колеса из него не нарисовать) и заканчивается у левого края панели. Места под
  неё не резервируется, пока её нет — низ колеса открыт. Над колесом тема оставляет не 72 px, а 30
  (`parts.titleGap`, лапа выступает над ободом не больше чем на 26 px), поэтому колесо выше и крупнее. Тексты темы —
  в локалях под `themes.taiwan.*`. При «уменьшить движение» нет наезда и пролётов, персонажи и строка не выезжают, а
  проявляются, бегущая строка стоит, смена фото остаётся.

## Веб-шрифты

Тема может подключать собственный шрифт, но только локальный: файл лежит в `public/fonts/<name>/` (Vite отдаёт
его как `/fonts/<name>/<file>`), рядом обязателен `LICENSE.txt` с автором, источником, датой скачивания и
условиями лицензии. Шрифты из сети (Google Fonts и подобное) не подключаем.

Как подключить (эталон — `src/domains/theme/themes/matrix/matrix.css` и `public/fonts/matrix/`):

1. `@font-face` объявляется в css-файле внутри папки темы и импортируется из `theme.ts` побочным импортом
   (`import './matrix.css';`). Так шрифт регистрируется вместе с реестром тем без правок общих файлов.
   Обязательно `font-display: swap`, иначе текст в DOM исчезнет на время загрузки.
2. В токенах семейство ставится первым в стеке, за ним запасные системные шрифты:
   `'"Matrix Title", "Courier New", Courier, monospace'`. Куда ставить — зависит от покрытия глифов (см. п. 4):
   как минимум `ui.headingFont`, при полном покрытии — также `ui.uiFont` и `select.fontFamily`.
3. Подписи секторов рисуются на canvas, а холст колеса кешируется и перерисовывается только при смене
   участников или подсветки (см. «Части колеса»). Пока шрифт не загружен, `ctx.font` молча берёт запасной, и
   подписи так и остались бы в нём. Поэтому компонент колеса должен перерендериться, когда шрифт приедет:
   вызовите `useFontReady('20px "Matrix Title"')` из `src/domains/theme/lib/useFontReady.ts` внутри своего
   `*SpinningWheel` и используйте результат в `renderer` (например, выбирайте семейство: до готовности —
   запасной стек, как `labelFont` в `MatrixWheel`). Хук вызывает `document.fonts.load`, помнит уже загруженные
   шрифты между монтированиями и никогда не зависает в `false`, даже если файл не загрузился. Смена значения
   меняет объект `renderer`, и `CanvasSpinningWheel` пересобирает кеш холста.
4. Проверьте покрытие глифов. Шрифт «Матрицы» (`matrix.ttf`) — только капитель: строчные буквы отображаются
   теми же заглавными глифами, цифр и кириллицы в нём нет. Браузер подставляет недостающие глифы из следующих
   шрифтов стека, поэтому русский интерфейс получился бы вперемешку из двух гарнитур. Отсюда правило: такой
   шрифт стоит только в `headingFont` (имя победителя, кнопка «Крутить») и в подписях секторов, а `ui.uiFont` и
   `select.fontFamily` остаются на моноширинном стеке. Не приводите строки к верхнему регистру в коде: шрифт
   делает это сам, а запасные шрифты при этом сохраняют обычный регистр. Синтетическое `bold` для потёртых
   глифов не используйте — оно их размазывает.

## Интерфейс (`ui`)

Токены пишутся в CSS-переменные `--theme-*` (`src/domains/theme/ui/ThemeRoot.tsx`) и в Mantine
(`src/app/MantineProvider.tsx`). Что они меняют:

| токен             | где виден                                                        |
| ----------------- | ---------------------------------------------------------------- |
| `colorScheme`     | светлая или тёмная схема Mantine (текст, инпуты, модалки)        |
| `accent`          | кнопка «Крутить», активная вкладка, чекбоксы, фокус              |
| `headingFont`     | имя над колесом, оверлей победителя, кнопка «Крутить»            |
| `headingColor`, `headingGlow` | цвет и `text-shadow` тех же заголовков               |
| `uiFont`          | остальной текст панели (необязательно)                           |
| `panelBackground`, `panelBorder`, `panelBlur` | карточки панели справа                  |
| `buttonRadius`, `buttonGlow` | форма и свечение кнопки «Крутить»                     |

Начинайте с `...DEFAULT_UI_TOKENS` и переопределяйте нужное. Для светлой темы `colorScheme: 'light'` и
светлые `panelBackground` с тёмным `headingColor`.

## Селект (`select`)

`background` (можно градиент), `color`, `borderColor`, `fontFamily`, `icon` (один символ). Эти же токены
красят пункт в выпадающем списке, поэтому список работает как палитра тем.

## Проверка

- `pnpm exec tsc --noEmit` и `pnpm exec eslint src/domains/theme/themes/<id> --ext ts,tsx --max-warnings 0`
  должны проходить.
- Визуально: 19 участников с длинными именами (список по умолчанию), окна 1366×768 и 1920×1080, прокрут
  3 секунды, оверлей победителя. Скриншоты снимает тот, кто ведёт интеграцию (один общий браузер).
- Никаких правок вне папки темы. Общие файлы (`themes.ts`, локали, `BaseWheel`) меняет интегратор.
